# CS255DriverPass
CS 255 Project Reflection

Briefly summarize the DriverPass project. Who was the client? What type of system did they want you to design?
The client was DriverPass which was a driving school that wanted a system that offered real world educational solutions to help students prepare for their driving test. We interviewed Liam (owner) and Ian (IT officer) to gather requirements. After that, we designed a system covering bookings, package selection, payment processing, and progress tracking. This was built out through a use case diagram, activity diagrams, sequence diagram, class diagram, and full System Design Document.

What I did well 
The use case diagram had to be my strongest component of the project. Pulling six actors and fifteen use cases straight from the interview and getting the include and extend relationships right gave me a strong foundation. I was able to trace back to the use case diagram later in the project.

What I'd revise 
I'd revisit payment processing. The transcript did not really address refunds or partial payments. I built around what was stated instead of pushing for more detail there during requirements gathering.

Interpreting user needs
I stuck close to what Liam and Ian said instead of assuming common driving school features. Considering user needs matters because a system that doesn't match how people operate fails no matter what it looks like on paper.

My approach going forward
I start with requirements and then build the use case diagram to map scope. I would then generate activity and sequence diagrams for logic. Then follow it up with generating the class diagram for structure. Going forward, I would focus more on building more client check ins throughout.
